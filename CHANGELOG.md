# 更新日志 / Changelog

## 0.1.5（2026-11-11） / 0.1.5 (2026-11-11)

0.1.5 于 2026-11-11 发布。可以只读导入真游戏的一局，预览种子，把已经写好的游戏 mod DLL 翻成 YAML，并在官方安装包里接上 `mentor-full`。组牌可以选择遭遇。两份保存的牌组可以对打同一份遭遇。长测试能看到进度，也能在两场之间取消。一份牌组可以看每张牌对胜率的影响。战斗可以同时开多个进程。界面有「本版更新」。侧栏可以在简体中文和 English 之间切换。跑完的结果可以打成 `.deckbench.zip`。没有游戏文件时，空的历史页可以载入一份自带的小样本。这一节开头的修复：`x-lang` 接受 BCP-47 别名；历史里未完成的测试，只要有打完的场次就显示胜率；导进来的结果再导出时，牌组预设还在；取消了的单卡贡献可以打包。版本号仍是 `0.1.5`，只写在 `sts2sim.__version__`。Windows 安装包的文件名是 `DeckBench-0.1.5-win64.zip`。发布说明在 `docs/RELEASE_0.1.5.md`。

*0.1.5 was released on 2026-11-11. You can import a real run read-only, preview a seed, turn a game-mod DLL you already built into YAML, and attach `mentor-full` from the official package. A deck preset can choose encounters. Two saved decks can fight the same encounters. A long test shows progress and can be cancelled between fights. A saved deck can show which cards help or hurt the win rate. Fights can run on more than one process at once. The GUI has a What's new page. The sidebar switches between 简体中文 and English. A finished result can be packed as a `.deckbench.zip`. With no game files, an empty History page can load a built-in sample. The fixes at the top of this section: the `x-lang` header accepts BCP-47 aliases; History shows a win rate for an unfinished test once any fight has finished; re-exporting an imported result keeps the deck preset; a cancelled card-impact job can be packed. The version stays `0.1.5`, written only in `sts2sim.__version__`. The Windows download is `DeckBench-0.1.5-win64.zip`. Release notes: `docs/RELEASE_0.1.5.md`.*

### 修复

- **`x-lang` 接受 BCP-47 别名，和 `?lang=` 共用一个归一函数。** `zh-CN`、`zh-Hans`、`zh`、`en-US`、`ja-JP`、`ko-KR`（大小写不限，下划线也行）收成 zhs / en / ja / ko。认不出的头仍忽略，不把已保存的语言盖成英文。
  *The `x-lang` header accepts BCP-47 aliases through the same normalizer as `?lang=`. `zh-CN`, `zh-Hans`, `zh`, `en-US`, `ja-JP` and `ko-KR` (any case; underscores too) map to zhs / en / ja / ko. An unrecognized header is still ignored, so a saved language is not replaced with English.*
- **历史的结果列会显示未完成测试的胜率。** 状态不是完成时，以前一律是破折号，取消或导入的部分结果也一样。现在只要有打完的场次，就显示胜率，并标上已有的「部分结果」（en / zhs / ja / ko 的 `run.partial`）。一场都没打完才留破折号。
  *History's result column shows the win rate for a run that is not done. It used to be an em dash for every status other than done, including a cancelled or imported partial run. Finished fights now show the win rate with the existing Partial tag (`run.partial` in en / zhs / ja / ko). The dash stays only when no fight has finished.*
- **导进来的结果再导出时，牌组预设还在。** 导入把 `preset.yaml` 放在测试目录里，不写回预设目录。再导出时，如果本机已经没有这份牌，或者示例包的 meta 里没有 `preset` id，以前会把预设丢掉。现在用测试目录里的那一份。
  *Re-exporting an imported result keeps the deck preset. Import stores `preset.yaml` in the run folder and does not copy it back into the presets directory. A second export used to drop it when that preset file was already gone, and the sample bundle's meta has no `preset` id. The export now reads the copy in the run folder.*
- **取消了的单卡贡献可以打成结果包。** `workers` 大于 1、全体场数仍在 400 以内时，取消会留下已经开打的变体；还没开始的变体没有 `raw.jsonl`。导出整包以前因此 404。没开打的变体现在以空的 `raw.jsonl` 进包，已经打完的场次仍在。
  *A cancelled card-impact job can be packed. With `workers` above 1 and the fight total still within 400, cancel keeps the variant that already started. A variant that never started has no `raw.jsonl`, and exporting the bundle used to answer 404. That variant is now packed with an empty `raw.jsonl`. Fights that finished stay in the file.*

  *With no game files, an empty History page can load a built-in sample. The encounter fixture in the tests has 12 HP and does not attack, so it never deals damage. `tools/make_demo_bundle.py` uses the synthetic monsters the tests already fight (`sts2sim.fightcheck`: 蛮兵, 术士, 荆棘). That is not a game encounter, and it is not the training dummy. The existing combat worker runs two shipped probes, `probe_noengine` and `probe_D`, 30 fights each, with the shipped full-fight cap of 30 turns. Fight indexes 0–29 use the worker's own seeds. Both sides store `shared_plan`, so the #67 bundle `gui/demo/sample.deckbench.zip` has manifest kind `head_to_head`. In this simulation, the no-engine probe is 20 wins and 10 losses, about 74 HP lost and 9.3 turns; route D is 30 wins, 45 HP lost and 2 turns. The compare deltas are not zero. Empty History has **Load demo data**. `POST /api/demo/load` and MCP `load_demo` (also on `--import-only`) use the same `import_zip_bytes` as `POST /api/bundles/import`. The Windows package puts the zip in `sim/gui/demo/`. A test regenerates the script, checks every fight aside from per-fight time, and imports the result. Simulation, seeds and AI are unchanged, and card text and win rates are not invented. See `docs/BUNDLES.md`.*

### 结果包

- **可以把一次已经跑完的测试打成一个 `.deckbench.zip`，再在另一台 DeckBench 里导回来。** `GET /api/runs/<id>/bundle` 导出一次测试。单卡贡献会把父任务和每个变体装进同一个包。`GET /api/runs/compare/bundle?a=<id>&b=<id>` 导出两次战斗实验；两边都是同一份对打时，清单的 `kind` 是 `head_to_head`。包里有 `manifest.json`、`meta.json`、`raw.jsonl`（整局是 `runs.jsonl`）、有牌组预设时的 `preset.yaml`，以及 #56 那份离线 HTML。清单写 `sts2sim.__version__`、schema 版本（当前是 1）和每个文件的 SHA-256。读写都是二进制，不把换行改成 CRLF，所以同一份字节在 Windows 和别的系统上哈希相同。成员名里的反斜杠在看清单之前就拒绝。运行页、报告页和对比页有「下载结果包」。历史页有「导入结果包」。`POST /api/bundles/import` 和 MCP `import_bundle` 校验清单和哈希，拒绝 `..`、绝对路径、反斜杠和超限文件，并且不执行包里的任何内容。schema 不是 1 时，说明里写明当前只读 schema 1。导进来的测试带 `imported` 和 `origin`（来源版本、原编号、导入时间），状态仍是原来的 `done` 或 `cancelled`，所以出现在测试列表里，也能参与对比。编号已经存在时换一个新编号。MCP `export_bundle`（`--import-only` 也有）把 zip 写到允许的目录并返回 `path`。不改模拟、种子和 AI。见 `docs/BUNDLES.md`。
  *A finished test can be packed into one `.deckbench.zip` and imported on another DeckBench. `GET /api/runs/<id>/bundle` exports one test. A card-impact job packs the parent and every variant into the same file. `GET /api/runs/compare/bundle?a=<id>&b=<id>` exports two combat tests; when both sides are the same head-to-head, the manifest `kind` is `head_to_head`. The zip holds `manifest.json`, `meta.json`, `raw.jsonl` (a full run has `runs.jsonl` instead), `preset.yaml` when the run used a deck preset, and the offline HTML from #56. The manifest records `sts2sim.__version__`, the schema version (currently 1), and a SHA-256 of each file. Reads and writes are binary, so a newline is not turned into CRLF and the hash matches on Windows. A backslash in a member name is rejected before the manifest is read. The run page, the report page and the compare page have **Download bundle**. History has **Import bundle**. `POST /api/bundles/import` and MCP `import_bundle` check the manifest and the hashes, reject `..`, absolute paths, backslashes and oversized members, and do not execute anything in the bundle. A schema other than 1 is refused with a message that says this DeckBench only reads schema 1. An imported test is marked `imported` and keeps `origin` (the source version, the original id, and the import time). Its status stays `done` or `cancelled`, so it shows up in the run list and can be compared. An id that is already in use gets a new id. MCP `export_bundle` (also on `--import-only`) writes the zip inside an allowed folder and returns `path`. Simulation, seeds and AI are unchanged. See `docs/BUNDLES.md`.*

### 中英切换

- **侧栏可以在简体中文和 English 之间切换。** 同一菜单里仍有日本語和한국어。选择写在这个浏览器的 `localStorage`（`ui.lang`），并优先于数据目录的 `settings.json`。没有记住的选择时用 `navigator.language`：以 `zh` 开头的是简体中文（页面 `lang` 为 `zh-CN`），日语是日本語，韩语是한국어，其他是 English。界面自己的句子在 `gui/locales/en.json` 和 `gui/locales/zhs.json`，日语和韩语用同一套键。一边有键、另一边没有，测试会失败。新建测试、运行、对比、组牌（对打、单卡贡献、进度和取消）、校准、关于、检查更新、本版更新的面板，以及错误和提示，都走这套文案。卡牌、遭遇、遗物和原版角色的名字，只在模拟器已经读到的游戏文本里有标题时才显示那个标题。不把 id 拆成英文，也没有游戏文本时不另填中文角色名；没有就显示原来的 id，或卡面上已经写的名字。离线 HTML 仍可用，`lang` 可以指定这份文件的语言。不改模拟、种子和 AI。见 `gui/README.md`、`docs/DECKS.md`、`docs/EXPORT.md`、`docs/CI.md`。

Our own sentences live in `gui/locales/en.json` and `gui/locales/zhs.json`. 日本語 and 한국어 use the same keys. A key that exists on only one side fails the test. ### 战斗进程

- **新建测试、组牌预设、连战、对打和单卡贡献可以同时打多场。** `workers` 省略时是 1，和原来一场接一场相同。上限是 `min(cpu_count, 8)`，再大也会收到这个数。用的是 spawn 进程（Windows 和 PyInstaller 里都先走 `freeze_support`，子进程不会再开一次界面）。每场种子不变，结果文件仍按原来的场次顺序写。连战不在一条种子里面并行：同一条种子上的遭遇按顺序打，不同种子可以同时打。取消仍是 #61 的规则：不再派发新的一场，正在打的打完，状态是 `cancelled`，`partial` 为 true。新建测试的战斗页和 `#/decks` 上有选择器，默认 1。`POST /api/runs`、`POST /api/decks/head_to_head`、`POST /api/decks/<id>/card_impact`，以及 MCP `head_to_head` / `card_impact`，都认这个参数。整局批量原来的进程滑块不动。不改模拟器的出牌、种子、AI，也不改出厂实验。这一台 4 核、Python 3.12 的机器上，200 场训练木桩（1 回合，启发式）workers=1 是 0.172 秒（1163 场/秒），workers=4 是 0.359 秒（557 场/秒）：单场太短，进程启动比战斗贵。同一份木桩改成束搜索、8 回合，200 场从 2.362 秒（84.7 场/秒）降到 0.902 秒（222 场/秒）。两边的 `raw.jsonl` 除每场用时外一致。见 `docs/DECKS.md`、`docs/PERFORMANCE.md`。
  *New test, a saved deck, a gauntlet, a head-to-head and a card impact can run fights at the same time. Omitting `workers` is 1, the same one-after-another behaviour as before. The cap is `min(cpu_count, 8)`; a larger number is reduced to that. The pool is spawned (`freeze_support` on Windows and in the PyInstaller package, so a child does not open the app again). Per-fight seeds stay the same, and result files stay in the original fight order. A gauntlet is not parallel inside one seed: encounters on that seed stay in order, and different seeds can run together. Cancel is still the rule from #61: new fights are not dispatched, the one in flight finishes, the status is `cancelled` and `partial` is true. The combat side of New test and `#/decks` have a selector, default 1. `POST /api/runs`, `POST /api/decks/head_to_head`, `POST /api/decks/<id>/card_impact`, and MCP `head_to_head` / `card_impact` all take the parameter. The existing process slider for full runs is unchanged. Simulator play, seeds, AI and the shipped experiments are unchanged. On this 4-core Python 3.12 machine, 200 training-dummy fights (1 turn, heuristic) took 0.172 s with workers=1 (1163 fights/s) and 0.359 s with workers=4 (557 fights/s): each fight is shorter than starting a process. The same dummy with the beam agent and 8 turns, 200 fights, went from 2.362 s (84.7 fights/s) to 0.902 s (222 fights/s). The two `raw.jsonl` files match aside from per-fight time. See `docs/DECKS.md` and `docs/PERFORMANCE.md`.*

### 版本号和检查更新

- **Windows 安装包用仓库里已有的版本号，并且可以手动查一次更新。** 版本号仍是 `0.1.5`，只写在 `sts2sim.__version__`。`gui/packaging/read_version.py` 读这一处。`build.ps1` 不写 `-Version` 时用它给 zip 起名（现在是 `DeckBench-0.1.5-win64.zip`），并写成 `VERSION.txt` 和 PyInstaller 的文件版本（`ProductVersion` 是 `0.1.5`，四段文件版本是 `0.1.5.0`）。反编译器工程不另写一个版本号；发布时用 `-p:Version=`、`-p:FileVersion=`、`-p:AssemblyVersion=`、`-p:InformationalVersion=` 盖上同一个数。`GET /api/version` 返回 `{"name":"DeckBench","version":"0.1.5"}`，和 `GET /api/health` 的 `version` 相同。页脚显示 `DeckBench v0.1.5`，点开「关于」也能看到。`gui/packaging/smoke_api.ps1` 核对 `/api/version`、`VERSION.txt` 和 exe 的文件版本。打包脚本仍是纯 ASCII，或带 BOM 的 UTF-8。
  *The Windows package uses the version the repository already has, and updates are a manual check. The version is still `0.1.5`, written only in `sts2sim.__version__`. `gui/packaging/read_version.py` reads that assignment. When `-Version` is omitted, `build.ps1` uses it for the zip name (today `DeckBench-0.1.5-win64.zip`), `VERSION.txt`, and the PyInstaller file version (`ProductVersion` `0.1.5`, four-part file version `0.1.5.0`). The decompiler project does not store a second number; publish stamps the same one with `-p:Version=`, `-p:FileVersion=`, `-p:AssemblyVersion=` and `-p:InformationalVersion=`. `GET /api/version` returns `{"name":"DeckBench","version":"0.1.5"}`, the same `version` as `GET /api/health`. The footer shows `DeckBench v0.1.5`, and About shows it too. `gui/packaging/smoke_api.ps1` checks `/api/version`, `VERSION.txt` and the exe file version. Packaging scripts stay pure ASCII, or UTF-8 with a BOM.*
- **「检查更新」默认关闭，不会在后台联网。** 关于对话框里的按钮调用 `POST /api/updates/check`，向公开的 GitHub API 查询 `Nopsil/deckbench` 的最新 Release，用 semver 和当前版本比较。已是最新写「Up to date.」，有更新写「New version X available.」并给出发布页链接。离线、速率限制、还没有 Release、标签不是版本号，都返回说明，不抛栈。可选的 MCP 工具 `check_update`（`--import-only` 也有）做同一件事，也是只有调用时才联网。见 `docs/DEVELOPER.md`、`docs/MCP.md`。
  *Check for updates is off unless you ask, and nothing phones home in the background. The button in About calls `POST /api/updates/check`, which reads the latest release of `Nopsil/deckbench` from the public GitHub API and compares semver with the current version. Up to date says “Up to date.” A newer release says “New version X available.” and links the release. Offline, a rate limit, no release yet, or a tag that is not a version returns an explanation and does not raise. The optional MCP tool `check_update` (also on `--import-only`) does the same thing, and it also waits until it is called. See `docs/DEVELOPER.md` and `docs/MCP.md`.*

### 单卡贡献

- **一份保存的牌组可以看每张牌是在帮胜率还是在拖后腿。** `#/decks` 上选一份预设，`POST /api/decks/<id>/card_impact` 用已有的战斗测试做留一法：基线，加上每种牌少一张；`plus` 为真时再多一张。遭遇、种子、回合上限和卡组 id 都相同，所以播种不变。全体合计不超过 400 场，默认按比例缩小场数，`scale: false` 或缩完仍放不下就拒绝。马上返回父任务 id 和每个变体的测试 id。进度和取消用 #61 的那一套，id 用父任务。`GET /api/decks/<id>/card_impact` 和 `GET /api/runs/<job>/card_impact` 给出变体减基线的胜率、平均掉血、平均回合、局数，以及 Wilson 区间。样本小于 30，或两侧区间重叠，`noisy` 为真。页面上的表可以按差值排序。离线 HTML 带上同一张表。MCP `card_impact`（`--import-only` 也有）开跑或读取结果。不改模拟器的出牌、种子和 AI，也不编造牌面数据。见 `docs/DECKS.md`。
  *A saved deck can show which cards help or hurt. **Deck builder** (`#/decks`) picks a preset. `POST /api/decks/<id>/card_impact` runs leave-one-out with the combat test that already exists: the baseline, plus one copy removed from each unique card, and one extra copy when `plus` is true. Encounters, seed, turn cap and deck id stay the same, so seeding stays the same. The whole ablation stays within 400 fights. The default scales fight counts down; `scale: false`, or a list that still does not fit, is refused. The response returns the parent id and each variant's run id immediately. Progress and cancel are the ones from #61, using the parent id. `GET /api/decks/<id>/card_impact` and `GET /api/runs/<job>/card_impact` return the variant-minus-baseline win rate, average HP lost, average turns, the sample size, and a Wilson interval. `noisy` is true when a side has fewer than 30 fights or the two intervals overlap. The table on the page sorts by delta. The offline HTML includes the same table. MCP `card_impact` (also on `--import-only`) starts a run or reads the result.
