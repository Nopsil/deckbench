- **图形界面可以翻看决策说明日志**。侧栏「决策说明」（`#/explain?path=`）只读打开 `--explain` 写下的 JSONL。日志路径和 MCP 的 `explain_fight` 用同一组允许目录。选一个种子和一场战斗后，按回合列出选了什么、前几名候选和分数，以及比第二名高多少；分差在 0.5 以内标成「分差很小」。候选上的 `thorns:` / `armour` / `incoming:` 备注会显示出来。阅读和分页走 `explain_fight`，不另写一套解析，也不写文件。
  *The GUI can page an explanation log. **Decisions** (`#/explain?path=`) reads a JSONL file written by `--explain`. The path has to sit in the same folders as MCP `explain_fight`. After a seed and a fight are chosen, each turn shows the choice, the top candidates with scores, and how far that choice was ahead of the runner-up. A gap of 0.5 or less is marked as a close call. Candidate notes such as `thorns:` / `armour` / `incoming:` are shown when the log has them. Reading and pagination go through `explain_fight`; the page does not parse the log a second way and does not write.*
- **启发式和束搜索可以选开荆棘、受击加格挡和多只敌人的总伤害**。默认关，固定种子的结果与原来相同。打开：构造参数 `mechanic_aware=True`、实验 YAML 的 `agent_kw: {mechanic_aware: true}`，或 `--mechanic-aware`（`--no-mechanic-aware` 仍表示关）。有荆棘时能量够就先格挡再打多段，自伤算进这一步的分数；已经有格挡的目标不是致命就不要把伤害撒上去；多只敌人的意图伤害先和自己的格挡比，纯攻击盖不住又没打掉威胁就先格挡。牌堆只按张数当成未知风险，不看是哪张牌，也不多抽随机数。`--explain` 的候选 `note` 写 `thorns:` / `armour` / `incoming:`。
  *Heuristic and beam can opt in to thorns, block gained when hit, and the sum of incoming damage. Off by default, so a fixed seed matches the previous result. Turn it on with `mechanic_aware=True`, `agent_kw: {mechanic_aware: true}` in the experiment YAML, or `--mechanic-aware` (`--no-mechanic-aware` still means off). With energy for both, they block before a multi-hit into thorns and count that self-damage in the action score; they do not spread hits onto a target that already has block unless the hit kills; they compare total incoming damage with block before a pure attack that does not remove the threat. Unseen draw and discard piles count by size only, with no extra random draw. `--explain` candidate notes read `thorns:` / `armour` / `incoming:`.*

- **内部战斗引擎加速，固定种子的结果逐字段不变**。复制战斗改为按字段拷贝，事件分发按类缓存，同一次决策不重复估值。`tools/batch.py` 和 `tools/ab_card.py` 增加 `--workers N`（等同 `--procs`；两个都给时以 `--workers` 为准），`python -m sts2sim` 的 `--workers N` 等同 `--jobs`。每场随机数不随进程数改变。
  *Faster internal fight engine with field-identical fixed-seed results. Fight copies are field copies, event dispatch is cached per class, and a decision evaluates the position once. `tools/batch.py` and `tools/ab_card.py` gain `--workers N` (same as `--procs`; `--workers` wins if both are set). `python -m sts2sim --workers N` is the same as `--jobs`. A fight's RNG does not depend on the process count.*
- **MCP 可以只读分析已经跑完的结果，不用打开图形界面**。`batch_run_summary(path)` 读一份整局 `runs.jsonl`（或含它的运行目录），返回和报告页相同的摘要，含胜率、Wilson 95% 区间和 `sample_warning`（数字来自 `sts2sim/stats.py`）。`card_ab(a, b)` 读两组已经跑完的结果；`b` 留空时，`a` 是目录，且里面恰好一对 `A.jsonl` / `B.jsonl` 或 `*_A.jsonl` / `*_B.jsonl`。返回 `p_value`（`sts2sim/stats.py` 的两比例 z 检验）以及和 `/api/ab` 相同的对照；不新开模拟。`explain_fight(path, fight, seed, offset, limit)` 读 `--explain` 写的 JSONL，按一场战斗分页返回每步已经记下的前几名候选。三条都只读：不写文件；路径必须在界面数据目录、DeckBench 缓存、`DECKBENCH_MCP_RUNS` 或 `DECKBENCH_ANALYSIS_ROOTS` 里，目录外的路径、存档树和 `.run` / `.save` 会拒绝。`--import-only` 也提供这三条，仍然没有对战工具和 `seed_preview`。只读的 `calibrate` 在上面的校准报告里，同样挂在 `--import-only`。见 `docs/MCP.md`。
  *MCP can read finished results without the GUI. `batch_run_summary(path)` reads a full-run `runs.jsonl` (or a run directory that contains one) and returns the same summary as the report page, including win rate, the Wilson 95% interval and `sample_warning` (from `sts2sim/stats.py`). `card_ab(a, b)` reads two finished result files. When `b` is empty, `a` is a directory with exactly one pair of `A.jsonl` / `B.jsonl` or `*_A.jsonl` / `*_B.jsonl`. It returns `p_value` (the two-proportion z-test in `sts2sim/stats.py`) plus the same comparison as `/api/ab`; it does not start a simulation. `explain_fight(path, fight, seed, offset, limit)` reads a `--explain` JSONL and pages one fight, with the top candidates already recorded for each decision. All three are read-only: they do not write, and a path outside the GUI data directory, the DeckBench cache, `DECKBENCH_MCP_RUNS` or `DECKBENCH_ANALYSIS_ROOTS` is refused, as are save trees and `.run` / `.save` files. `--import-only` exposes these three as well, still without play tools or `seed_preview`. Read-only `calibrate` is the calibration report above, and it is on `--import-only` too. See `docs/MCP.md`.*
- **修正战斗统计、存档导入、种子预览和报告里的几处边界**。过量伤害把生命停在 0，不再打成负数；中毒（以及会在扣血途中改生命的复活）按实际失去的生命计入，不再把整段层数算进去。存档里的 `NaN` / `Infinity` 当成这个字段没有，不再让整份记录抛 `ValueError`。Windows 上 `Sample.run` 与 `sample.run.backup` 视为同一局，发现存档时 `Current_Run.save` 也认。种子预览不再把「遭遇甲」这类名字拆成单字来计数或打印；缓存目录若通过符号链接指进仓库，或在 Windows 上只是大小写不同，会拒绝写入。非 ASCII 的卡牌 / 模组 ID 各自带稳定后缀，不会挤成同一个类名；纯 ASCII 的 ID 和前缀不变。报告能读 UTF-8 BOM 和 UTF-16（记事本另存的中文卡名），空行跳过；0 回合取胜不再写成「撑」。整局指标的层数中位数在偶数局里取中间值。`import_run` / `seed_preview` 的标准输出按 UTF-8 写，窄编码管道（例如 cp1252）不再在中文卡名上报 `UnicodeEncodeError`。
  *Fixes for combat totals, save import, seed preview and reports. Overkill stops at 0 HP instead of going negative, and poison (including a revive that rewrites HP mid-hit) counts the HP actually lost. `NaN` / `Infinity` in a save is a missing field instead of a `ValueError` for the whole file. On Windows, `Sample.run` and `sample.run.backup` are the same run, and discovery sees `Current_Run.save`. Seed preview no longer splits a name such as `遭遇甲` into characters when counting or printing; a cache directory that is a symlink into the repo, or the same path with different case on Windows, is refused. Non-ASCII card and mod ids get a stable suffix so they do not collapse to one class name; ASCII ids and prefixes are unchanged. ## 0.1.3 (2026-10)

- **修复：宝箱遗物从来没有真正拿到手。** 真游戏是在界面里发放宝箱遗物的，模拟器没有那个界面，所以以前所有模拟（批量、图形界面）里选了宝箱遗物也不会进遗物栏。现在默认修好（批量、图形界面、MCP 都一样）。**之前版本测出的胜率和层数都是在没有宝箱遗物的情况下测的**，会偏低，和新版本的数字不能直接比较；本说明下面引用的 AI 对比数字也是修复前测的。只为复现旧数字时可设 `DECKBENCH_TREASURE_FIX=0`。
  *Fix: treasure-room relics were never actually obtained. The game grants them through a UI element the simulator lacked, so in every earlier simulation (batch, GUI) the chosen chest relic never reached the relic bar. Now fixed and on by default everywhere (batch, GUI, MCP). **Win rates and floors measured with earlier versions were measured without chest relics** and are not directly comparable; the AI comparison numbers quoted below were also measured before the fix. Set `DECKBENCH_TREASURE_FIX=0` only to reproduce old numbers.*
- MCP：`act` 可以用 `option=` 按选项文字/ID 选（例 `option="JUGGLING"`、`option="跳过"`），比选项号稳定；一局结束时列出全部遗物和牌组。
  *MCP: `act(option=...)` picks by option text or ID; the end-of-run summary lists every relic and the full deck.*
- 新 AI「通用 AI（推荐，模组角色也能用）」（`modai`）：选牌、休息、商店交给一个只看通用数值、不看卡名的小网络，**模组角色也能用**，速度同学习版，Windows 可用。测试中原版角色平均多走约 1.5–4 层，Claude娘 A0 16.8 → 20.2 层。模型文件只有网络权重。`modai-boss`（加首领战推演）在 Windows 上隐藏。
  *New "General AI" (`modai`, recommended): a small character-agnostic network for card rewards, rest sites and shops (generic numbers only, no card names), so it works for mod characters; same speed as the learned AI, works on Windows. Weights-only model file. `modai-boss` is hidden on Windows.*
- 指定游戏种子：「新建测试 → 整局批量」可以填游戏里的种子（自动按游戏规则转大写、O→0、I→1），只打这一局并记录每一步的决策。命令行 `tools/batch.py --seed … --log-dir …`。
  *Play a real game seed: enter it in New Test (normalized like the game) to play that one run with a per-step decision log. CLI: `--seed`, `--log-dir`.*
- MCP 对战模式（从源码运行，可选 `requirements-mcp.txt`）：`tools/mcp_server.py` 让支持 MCP 的 AI 助手一步一步打一局，可撤销、恢复、导出操作清单。卡牌中文名运行时从你自己的游戏安装读取，不随项目分发。见 `docs/MCP.md`。
  *MCP play mode (from source, optional `requirements-mcp.txt`): `tools/mcp_server.py` lets MCP clients play a seeded run step by step with undo/restore/export. Card names are read from your own install at runtime and never shipped.*
- 可选的 spire-mentor AI：新增 `mentor-full-ev`（普通事件和锻造/删牌/变形/附魔选牌也交给它的 PPO，首领/精英战 4000 次模拟）；`--boss-sims` / `--elite-sims`。A10（每角色 60 局）：`mentor-full` 0/300 → `mentor-full-ev` 5/300。事件的英文文本运行时从你的游戏安装读取。
  *Optional spire-mentor agent `mentor-full-ev` (PPO also for regular events and out-of-combat card picks; 4000 sims in boss/elite fights) and `--boss-sims` / `--elite-sims`. A10 over 300 runs: 0 → 5 wins. Event text is read from your install at runtime.*
- 新模块 `sts2sim/gameloc.py`：从你的游戏 `.pck` 里读官方英文/中文本地化，只在内存里用（可用 `DECKBENCH_GAME_PCK`、`DECKBENCH_GAME_LOC_ENG` / `_ZHS` 覆盖）。
  *New `sts2sim/gameloc.py`: reads official English/Chinese localization from your own `.pck` at runtime, in memory only.*
